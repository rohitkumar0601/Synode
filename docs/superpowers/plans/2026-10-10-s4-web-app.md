# S4 — Web App (Next.js) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A polished web app where a non-technical user uploads (or picks) a tabular dataset, chooses generators, starts a benchmark, watches live progress, and reads a clean report: scorecard (mean ± std), privacy-gate results, the recommendation with its reason, preset/custom weights, and an interactive Pareto plot.

**Architecture:** `apps/web` — Next.js (App Router) + TypeScript + Tailwind + shadcn/ui; data fetching with TanStack Query (polling for live runs); Plotly (`react-plotly.js`, dynamically imported, client-only) for the Pareto plots; Recharts for scorecard bars. A typed API client (`lib/api.ts`) mirrors the S3 FastAPI contract; a Mock Service Worker (MSW) layer (`mocks/`) implements that contract in-browser for dev (`NEXT_PUBLIC_API_MOCK=1`) and in tests, so the app is buildable and demoable before S3 lands. Real API base URL: `NEXT_PUBLIC_API_URL` (default `http://127.0.0.1:8010`).

**Tech Stack:** Node 24, npm, Next.js (latest stable 15.x/16.x — whatever `create-next-app@latest` installs), React, TypeScript (strict), Tailwind, shadcn/ui, @tanstack/react-query, react-plotly.js + plotly.js-dist-min, recharts, msw, vitest + @testing-library/react + jsdom, eslint.

**Spec:** `docs/superpowers/specs/2026-10-05-synth-trust-lab-design.md` §9 (pages), §6 (metrics/presets). API contract: `docs/superpowers/plans/2026-10-07-s3-platform-api-queue.md` Tasks 3–5.

## Global Constraints

- **No git commits or pushes.**
- Dev server port **3010** (3000 is taken on the dev machine). API default `http://127.0.0.1:8010`.
- Windows + long OneDrive path: if `node_modules` installs or builds hit path-length errors, stop and report the exact failing path (do not move the repo). npm is the package manager.
- All API types live in `apps/web/lib/types.ts` and mirror the Python schemas field-for-field (snake_case kept, no renaming): `TableMetadata{columns: Record<string, "numerical"|"categorical"|"datetime"|"id">, target, task}`, `Dataset{id,name,source,target,n_rows,metadata,registered,fingerprint?}`, `GeneratorInfo{name,family,queue,cpu_ok,params,audit?}`, `RunJob{job_id,generator,seed,state,error}`, `Run{run_id,dataset_id,generators,seeds,preset,jobs,counts,done}`, `AxisScores{fidelity,utility,privacy}`, `RankedCandidate{generator,scores,score,gate_passed,gate_failures,on_pareto_front,notes?}`, `Recommendation{preset,weights,winner,reason,ranking}`, `AggregatedReport{generator,n_seeds,n_failed,mean,std,missing,worst}`, `RunReport{run_id,jobs_reported,jobs_total,recommendation|null,aggregated,pareto:[{generator,fidelity,utility,privacy,on_front,gate_passed}],per_job:[{job_id,generator,seed,status,warnings}]}`.
- Job states: `queued | fitting | sampling | generated | evaluating | done | failed`.
- Presets: `balanced (⅓,⅓,⅓)`, `privacy_first (0.2,0.2,0.6)`, `utility_first (0.2,0.6,0.2)`, custom (three non-negative weights, positive sum).
- Families shown with badges: `sanity_ceiling`, `sanity_floor`, `statistical`, `graphical`, `deep`, `diffusion`, `llm`, `differential_privacy`, `nominal_dp_audit` (label "audit — not DP", visually de-emphasised, unchecked by default). GPU-only (`cpu_ok=false`) generators show a "GPU" badge and are unchecked by default.
- Accessibility: keyboard reachable controls, labelled inputs, colour is never the only signal (gate pass/fail uses icon + text).
- Quality: `npm run lint`, `npm run typecheck` (`tsc --noEmit`), `npm test` (vitest, pristine), `npm run build` all pass.

## Review Focus

1. **API errors** (422/409/413/500/network down) show a readable message from the response `detail`, never a blank page. (Tasks 1–5.)
2. **A run whose jobs are still in progress** — report page shows partial results with "k of N jobs reported", keeps polling, and stops polling when `done`. (Task 4.)
3. **No generator passed the gate** — recommendation card shows the reason text and the per-generator failures, no winner highlight. (Task 4.)
4. **Missing metric values (null)** — rendered as "—", never "NaN" or "0". (Tasks 4–5.)
5. **Custom weights invalid** (all zero, negative) — inline validation, request not sent. (Task 4.)

### Task 4: Run detail — live progress, scorecard, recommendation, presets

**Files:** `apps/web/app/runs/[id]/page.tsx`, `apps/web/components/{job-progress.tsx,scorecard.tsx,recommendation-card.tsx,gate-failures.tsx,preset-switcher.tsx}`, `apps/web/app/runs/page.tsx` (list), tests.

**Behaviour:** `useQuery(getRun)` polls every 3 s while `!done`; progress bar (done+failed / total) and per-job rows with state badges, error tooltip for failed jobs. `useQuery(getReport)` keyed by preset/weights, polls while not done; header "k of N jobs reported". Recommendation card: winner (or "No generator passed the privacy gate"), reason text, notes (e.g. "singling-out not attackable"). Scorecard table: generator, family badge, fidelity/utility/privacy as mean ± std (`fmtMeanStd`), weighted score, gate (✓ pass / ✗ fail + first failure, expandable list), Pareto-front marker; sortable by score; gate-failing rows de-emphasised; audit family flagged. Preset switcher (tabs) + custom weights (sliders) refetch the report without reloading the run. Recharts horizontal bar chart of weighted scores (gate-pass coloured, fails grey, with pattern/icon too).

- [ ] Steps: tests first (polling stops when done; partial report label; no-winner state; nulls render "—"; preset change refetches with params) → implement → GREEN; checks. Checkpoint.
